# Card

A surface for grouping related content: a `white`, `light`, `medium` or `dark` background with a matching text colour, an optional border, square or rounded corners, and padding. Renders a `<div>` by default, or the element set by `as`.

## When to use

- Present one item of a collection — a project, an article, a feature — usually inside a [`GridGroup`](?path=/docs/components-layout-grid-group--docs).
- Render it `as="article"` for content that stands on its own, or `as="li"` inside a `GridGroup` rendered `as="ul"`.
- For a ready-made design, use a design card such as [`ProjectCard`](?path=/docs/components-cards-project-card--docs), which is built on `Card`. Use `Card` directly for custom one-off content.
- Don't use it for page sections with full-width backgrounds — that's [`Container`](?path=/docs/components-layout-container--docs).

## Import

```tsx
import { Card, CardLink } from '@troychaplin/parlour-ui';
```

## Basic usage

```tsx
// The defaults: a light background and border, square corners
<Card>…</Card>

// No border, rounded corners
<Card border={false} borderRadius="lg">…</Card>

// A dark card — the text turns white with it
<Card backgroundColor="dark" borderColor="dark">…</Card>

// Cards in a list
<GridGroup as="ul" gap="medium">
    <Card as="li">…</Card>
    <Card as="li">…</Card>
</GridGroup>

// The whole card as one link, named by its heading
<Card>
    <h3>
        <CardLink href="/work">Work</CardLink>
    </h3>
    <p>…</p>
</Card>
```

### Default

The defaults match the project cards: a `light` background (`neutral-50`), a 1px `light` border (`neutral-300`), square corners and `large` padding on every side.

### Without a border

`border={false}` drops the border, leaving the background to separate the card from what's around it.

### Padding

`paddingInline` sets the left and right padding and `paddingBlock` the top and bottom. Each takes any step of the spacing scale, or `none`, and both default to `large`.

<Canvas of={CardStories.Padding} />

### Rounded

`borderRadius` takes any radius token — `sm`, `md`, `lg`, `xl` or `full` — or `none`, the default.

<Canvas of={CardStories.Rounded} />

### Colours

`backgroundColor` takes `white`, `light`, `medium` or `dark`, and the text colour follows it: black on `white` and `light`, white on `medium` and `dark`. `borderColor` takes the same four names.

<Canvas of={CardStories.Colors} />

### In a dark Container

The card keeps its own text colour, so a light card inside a dark `Container` stays readable. Headings inside it follow the card's text colour rather than the container's white heading style.

<Canvas of={CardStories.InDarkContainer} />

### With a link

Put a `CardLink` inside the card — usually around the text of its heading — and the whole card becomes clickable. The link wraps only its own text; a `::after` overlay stretches it over the card, so a click anywhere on the card follows it. `CardLink` takes `href` and any other `<a>` attribute, such as `target` or `rel`, and a `className` is appended after `parlour-card__link`. The link comes from [`LinkProvider`](?path=/docs/components-utilities-linkprovider--docs), so it's your router's link component. [`ProjectCard`](?path=/docs/components-cards-project-card--docs) puts one in its title when `href` is set.

<Canvas of={CardStories.WithLink} />

### Background on hover

`backgroundHover` lays a translucent overlay over a linked card's background while the pointer is over it: `light` is white at 5% opacity, for `medium` and `dark` cards, and `dark` is black at 7%, for `white` and `light` cards. The overlay tints whatever surface sits under it, so the text colour stays the same. It only applies to a card holding a `CardLink`: hover feedback on a card that does nothing when clicked would suggest that it does. Here the cards sit flush in a [`GridGroup`](?path=/docs/components-layout-grid-group--docs) with `dividers="all"`.

## CSS classes

| Class                                 | When applied                                                                                                            |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `parlour-card`                        | Always — base class                                                                                                     |
| `parlour-card--bg-{name}`             | Always — the `backgroundColor` value, e.g. `parlour-card--bg-light` (default); also sets the text colour                |
| `parlour-card--bg-hover-{name}`       | `backgroundHover` is set — `light` or `dark`; the overlay applies only while the card holds a `CardLink` and is hovered |
| `parlour-card--border`                | `border` is true (default) — a 1px solid border                                                                         |
| `parlour-card--border-{name}`         | `border` is true — the `borderColor` value, e.g. `parlour-card--border-light` (default)                                 |
| `parlour-card--radius-{size}`         | Always — the `borderRadius` value, e.g. `parlour-card--radius-none` (default)                                           |
| `parlour-card--padding-inline-{step}` | Always — the `paddingInline` value, e.g. `parlour-card--padding-inline-large` (default)                                 |
| `parlour-card--padding-block-{step}`  | Always — the `paddingBlock` value, e.g. `parlour-card--padding-block-large` (default)                                   |
| `parlour-card__link`                  | On `CardLink` — its `::after` covers the card; the card's border darkens on hover while it holds one                    |

The padding modifiers set `--parlour-card-padding-inline` and `--parlour-card-padding-block`, which the card uses for its padding. The card is `position: relative`, so a `CardLink` overlay stays inside it.

The first child's top margin and the last child's bottom margin are removed, so the padding looks even. Headings inside the card inherit its text colour. A `className` you pass is appended after these classes.

## Design tokens

| Token                                   | Used for                                                                      |
| --------------------------------------- | ----------------------------------------------------------------------------- |
| `--parlour--color-white`                | `white` background; text on `medium` and `dark` cards; `white` border         |
| `--parlour--color-neutral-50`           | `light` background (default)                                                  |
| `--parlour--color-neutral-900`          | `medium` background; `dark` border                                            |
| `--parlour--color-neutral-950`          | `dark` background                                                             |
| `--parlour--color-black`                | Text on `white` and `light` cards                                             |
| `--parlour--color-neutral-300`          | `light` border (default)                                                      |
| `--parlour--color-neutral-500`          | `medium` border; border of a card holding a `CardLink` while hovered          |
| `--parlour--spacing-*`                  | `paddingInline` and `paddingBlock` — any step of the spacing scale, or `none` |
| `--parlour--radius-*`                   | `borderRadius` — `sm`, `md`, `lg`, `xl` or `full`                             |
| `--parlour--color-overlay-light`        | `backgroundHover="light"` — white at 5%, layered over the card's background   |
| `--parlour--color-overlay-dark`         | `backgroundHover="dark"` — black at 7%, layered over the card's background    |
| `--parlour--color-accent-primary`       | Focus outline around a card whose `CardLink` has focus                        |
| `--parlour--color-accent-primary-light` | The same outline on a `medium` or `dark` card                                 |
| `--parlour--transition-fast`            | Border colour change on a card holding a `CardLink`                           |

A `light` card (`neutral-50`) is a step lighter than a `light` [`Container`](?path=/docs/components-layout-container--docs) (`neutral-200`), so it stands out on a light section. The border's `1px` width and the `2px` focus outline are raw values rather than design tokens.

## Accessibility

- The default `<div>` adds no semantics. Use `as="article"` for a self-contained item, and `as="li"` when the card is one of a list.
- The background sets the card's own text colour, so its text stays readable whichever section it sits in, and headings inside it follow that colour too.
- Every background passes WCAG AA with its text colour: black on `white` is about 18:1 and on `light` about 16:1; white on `medium` is about 11:1 and on `dark` about 16:1.
- `CardLink`'s accessible name is its own text, such as the heading, so screen readers announce a short link and voice-control users can say what they see (WCAG 2.5.3 Label in Name). Wrapping the whole card in a link instead would make its name all of the card's text.
- Use one `CardLink` per card. The overlay sits above the card's other content, so another link or button inside the card needs `position: relative` and a `z-index` to stay clickable. Selecting text in a linked card is harder, as the overlay catches the pointer.
- `CardLink` is a client component (`'use client'`) because it reads `LinkProvider`; `Card` itself is not. Server components can render both.
- The link resets Main's bold, underlined link style so the card's text looks the same linked or not. While it has focus, the outline is drawn around the whole card.
- The hover overlay is a slight tint, so text keeps about the same contrast as on the card's own background. It's drawn as a `background-image`, so it adds to `backgroundColor` instead of replacing it.
- The border is decorative — it isn't needed to understand the content — so it isn't held to a contrast ratio.
